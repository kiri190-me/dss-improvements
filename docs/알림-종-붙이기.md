# 사내 사이트 머리말에 알림 종 달기

이 사이트(개선요청)에 붙인 방법을 그대로 적는다. **같은 일을 네 번 더 해야 한다**
(A/S · 계측기 · PO/내자 · 휴가). 포털 쪽 규격은
`dss-auth/docs/사이트-알림-통로.md`, 조각 쪽 설명은 `@dss/ui` 의 README 7절이다.
여기 적는 것은 **이 저장소에서 실제로 밟은 순서와 함정**이다.

## 고친 것 여섯 (2026-09-21, 이 저장소 기준)

| 자리 | 한 일 |
|---|---|
| `vendor/dss-ui` | 서브모듈 포인터를 종이 들어 있는 판으로 올린다 (`8a17da8`) |
| `tsconfig.json` | `"@dss/ui/notification-bell.css"` 경로 별칭을 더한다 |
| `src/app/layout.tsx` | `import "@dss/ui/notification-bell.css";` 한 줄 |
| `src/lib/auth/oidc.ts` | 포털에 묻는 `fetchPortalNotifications` (+ 순수 함수 `normalizePortalNotificationFeed`) |
| `src/components/PortalNotificationBell.tsx` | 서버에서 물어 종을 그리는 조각 |
| `src/components/AppHeader.tsx` · `src/app/(app)/layout.tsx` | `<Suspense>` 로 감싸 머리말 **맨 오른쪽 끝**에 내려보낸다 |

시험은 `src/lib/auth/notification-bell-wiring.test.ts` 한 장이고
`scripts/test-lists/unit.txt` 에 적혀 있다.

## 정한 것 둘과 까닭

**1. 서버에서 가져온다(브라우저가 아니라).** 자격증명이 `client_secret` 이라
브라우저에서는 부를 수 없다. 브라우저에서 가져오려면 사이트 안에 중계 통로를
하나 더 두고 거기서 세션을 다시 검증해야 한다 — **시크릿을 다루는 자리를 하나 더
만드는 일**이다. 서버에서 부르면 시크릿이 프로세스 밖으로 나가지 않고, 종은
자바스크립트 없이도 열리는 서버 조각으로 남는다.

🔴 그 대신 **`<Suspense>` 로 감싼다.** 머리말은 모든 화면에 딸려 오므로, 감싸지
않으면 **모든 화면 이동이 포털 왕복만큼 느려진다.** 감싸면 머리말과 본문이 먼저
뜨고 종만 나중에 흘러 들어온다. `fallback` 은 `null` 이다 — 알림이 없을 때와 같은
모습이라 자리가 들썩이지 않는다.

**2. 다시 묻는 주기는 두지 않는다.** 포털이 이미 30초 캐시를 들고 있어 그보다 자주
물으면 같은 답을 받고, 되묻는 장치를 붙이는 순간 위에서 피한 중계 통로가 도로
필요해진다. 종은 화면을 새로 열 때 갱신된다.

## 🔴 밟은 함정 다섯

1. **서브모듈 포인터.** 종은 `@dss/ui` 의 새 판에만 있다. 포인터가 옛 커밋이면
   `NotificationBell` 이 아예 없다. `git -C vendor/dss-ui fetch && git -C vendor/dss-ui checkout <sha>`
   로 올리고, **그 안의 파일은 고치지 않는다**(다섯 사이트가 함께 쓰는 저장소다).
2. **CSS 는 조각마다 한 장.** 메뉴바의 `@dss/ui/styles.css` 와 **다른 파일**이다.
   경로 별칭을 tsconfig 에 안 더하면 tsc 는 통과하는데 화면에서 스타일만 통째로
   빠진다.
3. **종은 줄의 맨 오른쪽 끝에.** 펼친 목록은 종에 오른쪽 끝을 맞춰 왼쪽으로
   펼쳐지고(`right: 0`) 폭이 폰에서 320px 이다. 종이 줄 가운데쯤 앉으면 **목록
   왼쪽이 화면 밖으로 잘린다.**
4. **래퍼 `<div>` 로 감싸지 않는다.** 그릴 알림이 없으면 조각이 스스로 `null`
   이라 종이 아예 안 그려지는데, 감싸면 빈 flex 항목과 그 앞 여백이 남아 머리말이
   달라진다. (「알림 없음」을 보여 주지 않는 것은 `@dss/ui` 의 결정이다 — A/S 의
   자체 종은 빈 종도 그린다.)
5. **어떤 답이 와도 던지지 않는다.** 포털이 죽었든(503) 거절했든(401·403·429)
   `.env` 가 비었든 **빈 목록**이 나가야 한다. `env` 의 getter 는 값이 없으면
   던지므로 **try 안에서 읽는다.** 왕복에는 반드시 상한(`AbortSignal.timeout`)을
   건다 — 응답 없는 주소를 두드리면 기본값으로는 하염없이 기다린다.

## 자체 알림이 있는 사이트라면

포털은 **부른 사이트 자신의 알림을 빼고** 준다. 자체 알림이 있으면 이어 붙이고
개수도 **더해야** 한다:

```tsx
<NotificationBell
  items={[...mine.items, ...feed.items]}
  count={mine.count + feed.count}
/>
```

이 사이트에는 자체 알림이 없어(개선요청은 상태를 옮길 때 누구에게도 알리지 않는다)
받은 것이 곧 전부다. A/S 는 자체 종이 있으므로 그쪽은 이어 붙이는 쪽이다.
개수는 **보낸 쪽이 센 값**을 쓴다 — 줄 수로 다시 세면 그 시스템의 종과 이 종이
서로 다른 숫자를 말하게 된다.

## 확인

```
# 포털 저장소에서 — 거절 여섯 가지와 정상 왕복을 진짜 서버에 대고 본다
SITE_ENV_FILE=../<사이트>/.env.local npm run check:notify:site
```

눈으로 볼 것 넷: ① 머리말에 종이 보인다(알림이 있을 때) ② 열면 다른 시스템 알림이
보이고 누르면 그 화면으로 건너간다 ③ 🔴 포털 주소를 틀리게 해도 사이트가 그대로
뜬다 ④ 콘솔에 오류·hydration 경고가 없다.
